问题分级 14 项

A 级 · 旅程断点（5）

  • A1invite_only 批次码无创建入口，策略产品上不可用
  • A2web 无「我的报名」；取消报名两端无 UI
  • A3Sponsor 提交意向后无状态查看；学员无进度页
  • A4web 零通知触达（无站内信/邮件）
  • A5无找回密码、无邮箱验证

B 级 · 错位与口径不一（6）

  • B1BYO 入口三层深、宿主工作台语义错位
  • B2入座角色：注册=member vs open=learner
  • B3Volunteer 邀请仅存在于 MCP 通道，三端口径不一
  • B42046 双重身份 → 草稿全员可见
  • B5平台管理员治理读被前端封死
  • B6权限映射页四行同权，展示有误导

C 级 · 规划断链（3）

  • C1Agent/Skill 零实现，任务指令模式断链
  • C2答疑分支（get_learner_history 等）待 v1
  • C3占位页与过时文案（/admin/openclacky 等）

改进建议 P1 → P3

P1 补断点

小成本高收益，尽快
  1. ★用户级「我的参与」页：我的报名（含取消）+ 我的赞助 + 学习进度——一页解决 A2/A3
  2. InviteBatch 管理面板，或 v1 裁掉 invite_only 选项
  3. 通知最小版：状态自助查询 + 角标；站内信列二期

P2 修错位

对齐语义与入口
  1. ★BYO 入口提级为用户级页面（/settings/connections）+ 概览页引导卡——根治 B1
  2. Workspace.join 入座 learner → member，统一词汇
  3. draft 收紧为管理角色可见（评估筹备协作影响）
  4. 平台管理员只读放行业务工作台

P3 断链（走 roadmap）

大工程，按既定规划排期
  1. Agent 指令最小版：workflows 页逐步展示「给助手的指令」文本，后续接 get_agent_instruction
  2. 找回密码 + 邮箱验证（依赖邮件服务，随 ICP 合规一起排期）
  3. 答疑分支 · 站内通知中心

待拍板的 5 个决策点

  1. 「我的参与」页范围：最简版（报名+取消）还是完整版（+赞助+学习进度）？
  2. invite_only：补批次码 UI，还是 v1 裁剪该策略？
  3. 自动入座统一为 member 是否接受（不迁移存量）？
  4. 2046 草稿可见性：收紧 draft 读权限 / 大厅约定 / 接受现状？
  5. 平台管理员要不要进业务工作台只读（复用页面 vs 只在 /admin 治理）？
