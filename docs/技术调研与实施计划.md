### 1.2 前端(Next.js 16 App Router + Apollo Client 4)

| 领域 | 决策 | 说明 |
|---|---|---|
| 渲染模式 | **全客户端渲染** | `"use client"` + `ApolloProvider` 在 root layout 包裹(RSC 只做壳)。平台是重交互应用(Agent 对话、Workflow 执行、审批流),SSR 收益低、复杂度高。**不引入** `@apollo/client-react-streaming` |
| 跨域 | **Next.js rewrite 代理** | `next.config.ts` 加 `rewrites()`:`/api/graphql` → `http://localhost:4000/api/graphql`,消除 CORS;后端 cors_plug 保留作双保险 |
| 认证传输 | **token 存 httpOnly cookie + Authorization header** | 登录 mutation 返回 JWT → 写 cookie → Apollo link 中间件读取附加 `Authorization: Bearer` |
| 对话流式 | **fetch(ReadableStream)消费 SSE** | 自建 `/api/agent_runs/:id/stream` endpoint;不用 GraphQL subscriptions(Absinthe 依赖重、实验性) |
| 状态管理 | **只用 Apollo cache** | 不引 Redux/zustand;需要再拆 |

### 1.3 明确不用的(调研排掉)

- `ash_rbac`:角色编译期写死,不匹配数据库 Role 实体 → 自研

- `ash_agent` / `ash_agent_session` / `ash_agent_tools`(第三方 bradleygolden):非官方、不成熟 → 用官方 ash_ai

## 二、关键调研结论(带证据)

### 2.1 Ash 多租户(hexdocs ash/multitenancy 已读)

- **attribute 策略**:租户资源加 `multitenancy strategy: :attribute, attribute: :workspace_id`;所有查询自动按 tenant 过滤。
- **set_tenant 必须在认证 plugs 之前**(`Ash.PlugHelpers.set_tenant(conn, tenant)`),因为 User/Token 校验需要正确的租户上下文。
- **全局资源**(User / Workspace)不带多租户;租户资源(User 之外的业务资源)带 `workspace_id`。
- Code interface / action 内可用 `Ash.Query.set_tenant/2`、`Ash.Changeset.set_tenant/2`;`Ash.Scope` 可打包 actor/tenant/context。
- **两个 Api 模块**:`Cgc2046.Api`(租户资源,默认要求 tenant)+ `Cgc2046.GlobalApi`(User/Workspace)。

### 2.2 ash_ai 0.8.1(hexdocs ash_ai,官方)

- `AshAi.Actions.Prompt`:通用 action 实现,用 ReqLLM 生成**结构化输出**,匹配 action return 约束(如 `:atom` + `one_of [:positive, :negative]`)。
- `AshAi.ToolLoop.run/2`(同步)/ `stream/2`(流式):**主编排 API**,管理 ReqLLM 对话循环含工具调用。
- MCP:`AshAi.Mcp.Dev`(dev 挂载)/ `AshAi.Mcp.Router`(prod,可配认证)。本平台 Agent 可以暴露为 MCP server(二期)。
- 底层 `req_llm` 1.17.1(基于 Req & Finch,依赖已含 `req`)。
- 向量检索:`AshPostgres.Extensions.Vector`(知识库二期)。
- **Mock 方式**:req_llm 走 Req,测试用 `Req.Test` 拦截即可,无需真实 LLM。

### 2.3 ash_authentication 4.14.1

- 策略:Password / ApiKey / Auth0 / Github / Google / MagicLink / Slack / OAuth2 / Oidc → **本平台用 Password(用户名+密码)+ 邀请链接**(MagicLink 作为备用体验)。
- Token:`AshAuthentication.TokenResource`(短期 JWT,`sign_in` mutation 返回);`Confirmation`(邮箱确认,邀请场景)。
- 前端集成:GraphQL `signIn(email:, password:)` → token → cookie → `Authorization: Bearer` 头;后端 `AshAuthentication.Plug` 验证。

### 2.4 AgentRun(执行记录/计费)

- **用 ash_oban 0.8.11 做后台执行**:AgentRun 状态机(pending → running → succeeded | failed | cancelled)+ Oban worker 执行 LLM 循环。
- 字段设计(前 chunk 已定):输入/输出、token 用量、耗时、状态、关联 Step/Agent。
- 流式:Oban worker 内 `ToolLoop.stream` 产出的增量 → `Phoenix.PubSub.broadcast` 或 SSE 推送 → 前端展示。
- 异步一致性:Oban 重试保证,不用复杂队列。

### 2.5 前端(Next.js 16 + Apollo 4)

- 脚手架现状:`app/apollo-provider.tsx`("use client" + ApolloProvider)、`lib/apollo-client.ts`(`createHttpLink` + `InMemoryCache`)、layout 已包裹。
- 补充:middleware/rewrite 代理;Apollo link 中间件加 Authorization;SSE 用 fetch stream。

## 三、自研 RBAC 设计(核心,需写清楚)

### 3.1 数据模型

```
User(全局) ─── WorkspaceMembership(1 条/人/租户) ──── MembershipRole(N:M) ──── Role(租户内)
                                                     MembershipRole.role_id ──→ Role.id
Workspace(全局, join_policy)  Role 挂 allowed_roles(Agent 资源引用 Role.id 集合)
```

### 3.2 判定逻辑

- **多角色**:一个成员多条 MembershipRole → 权限 = 所有角色权限**并集**,命中任一即放行。
- **Step 授权**:`StepRole` 关联表(step_id, role_id);执行动作时要求成员的角色集与 Step 允许角色集**有交集**。
- **Agent 授权**:Agent 资源 `allowed_roles: [Role.id]`(公共 Agent 独立授权)。

### 3.3 Ash 实现方式(不用 AshRbac)

- 每个租户资源 `policies` 里用**自定义 authorize** 或 `expression` 引用 Rbac 模块,示例:

```elixir
policies do
  policy action_type(:read) do
    authorize_if expr(workspace_id == ^actor_workspace_id)  # 租户内可见
  end

  policy action_type([:update, :destroy]) do
    authorize_if Cgc2046.Rbac.can?(actor, :manage, resource: __MODULE__)
  end
end
```

- `Cgc2046.Rbac.can?(actor, permission, opts)`:读 actor 的 memberships(membership + roles 预加载),并集展开权限集,返回布尔。
- 统一约定:**所有写操作(action)首行 `Rbac.ensure!(actor, :xxx)`**,失败返回 Forbidden。

## 六、风险与注意点

1. **AshRbac 不适用**(角色编译期)→ 自研 Rbac,注意"多角色并集"与"Step/Agent 交集"两种判定不要混。
2. **set_tenant 顺序**:放在认证 plugs **之前**,否则 User 校验拿不到租户上下文(全局资源除外)。
3. **ash_ai 0.8.1 较新**:API 可能有小变动;锁定版本(`{:ash_ai, "~> 0.8.1"}`),升级前看 changelog。
4. **不直接用 `ash_ai.gen.chat`**:其架构(Oban + pub_sub + 实验性)只借鉴;我们自建 SSE 更可控。
5. **多租户 + 全局混合**:User/Workspace 全局,其余全部租户;创建租户资源的 action 必须显式 set_tenant(从 actor 的 membership 取 workspace_id),防止跨租户写入。
6. **token 安全**:httpOnly cookie;登录 token 短期 + refresh(二期);邀请 token 存 hash(不存明文)。
7. **LLM 成本**:AgentRun 记录 token 用量,为计费/限流预留;生产加 rate limit。
