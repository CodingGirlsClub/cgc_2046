# 隐私指引草案（小程序 v1）— 手机号用途说明

> 状态：**草案**（交 human 审阅/修订后用于上架材料）
> 关联：原 2026-08 小程序实施计划的隐私交付物（计划文档已删，git 历史可溯）；多端边界见 `docs/01-定稿设计/小程序多端平台矩阵.md`
> 实现依据：`backend/lib/cgc_2046/accounts/user.ex`（phone 字段 `public?: false` + `sensitive?: true`）、`backend/lib/cgc_2046/miniprogram/client.ex`（session_key 不出后端）

## 1. 我们收集什么

- 用户在微信 / 抖音 / 小红书小程序内主动点按「XX手机号快捷登录」后，平台经 `getPhoneNumber` 授权返回的手机号。
- 登录态：平台登录凭证 code（换 openid/unionid/session_key），session_key 仅在后端调用栈内流转，**不进日志、不进数据库、不进任何响应**。

## 2. 手机号用于什么（用途限定）

| 用途 | 说明 |
|---|---|
| 账号创建与身份锚定 | 手机号是 CGC 账号的唯一锚点：同一手机号在微信/抖音/小红书登录自动归一到同一账号（跨平台归一） |
| 报名身份确认 | 报名记录归属到该账号；审批人可见报名者姓名/邮箱（非手机号） |
| 接收通知 | 审批结果 / 48h 提醒 / 活动开始提醒，经平台订阅消息送达（**每次订阅需用户主动授权，授权一次发一次**） |

## 3. 存储与保护

- 手机号以明文存于数据库（v1 社区平台风险已评审接受）。
- `phone` 字段标记为 sensitive：**不进入 GraphQL 响应、不进入日志 inspect**——任何用户（含本人）都不可经 API 读取手机号。
- 手机号归一化为 `+区号号码` 存储，跨平台共用唯一锚。

## 4. 不做什么

- 不向任何其他用户公开手机号（审批人看到的是姓名/邮箱）。
- 不用于营销、不用于第三方共享、不做画像。
- 不主动推送（微信一次性订阅语义：无授权即无推送）。

## 5. 用户控制

- 每次订阅通知均需在对应业务节点主动授权（报名提交后 / 审批前 / 报名成功后）。
- 拒绝授权不影响报名本身。
- 「我的」页可退出登录：服务端撤销当前 token（白名单吊销），本机清除登录态。

## 6. 合规定位（PIPL）

- 手机号为个人信息，处理目的限定于第 2 节；授权入口即同意告知（登录页声明「登录即表示你同意隐私授权说明」）。
- 正式上线前应补齐：隐私政策全文页、个人信息处理规则、客服/申诉渠道（见 ICP 材料清单）。

## 7. 已知边界

- 手机号回收后号码被他人注册可能造成账号接管（行业共有风险）；v1.5 计划加敏感操作二次校验与 Identity 变更审计。
- 删除账号/注销入口不在 v1 范围（v1.5 补）；v1 可退出登录停止使用。
