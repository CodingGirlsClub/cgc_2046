# R3：统一 Web 登录与注册入口

用户已确认并授权实施，对应 #1033；依赖 R2 #1032。本 PR 单独交付 Web 入口及清理，不改变 R1 的认证规则。

## 产品与账号规则

普通 `/login` 以微信快捷登录／注册为主，电脑显示小程序码，手机提供打开小程序入口；平台授权手机号并明确确认后，新号码建号，同号码复用原 User。已有用户仍可使用手机号／邮箱＋密码和原密码恢复流程。新用户没有微信时不能通过新的 Web 主流程注册；不恢复邮箱注册，不创建无手机号账号，不合并历史账号、不转移权限或业务数据。

`/register` 使用 Next.js 与既有 next-intl locale-aware redirect 汇入同语言 `/login`；仅透传非空单值 `next`，忽略其他参数。redirect 目标固定为站内 `/login`，最终登录回跳继续由既有同源校验处理。旧注册链接保留可达性，sitemap 不再单独索引注册重定向地址。

## 清理与保留边界

删除普通短信登录、短信注册表单和失去调用方的前端 GraphQL 操作。密码表单不再提供独立注册链接或抢占初始焦点。顶导将登录和加入按钮合并为登录／注册。

旧 `bind_ticket` 会话仍由专用 `LegacyWechatBindForm` 处理，不启动新小程序请求。共用发码逻辑移到 `lib/use-phone-code.ts`，仅负责 WECHAT_BIND／CHANGE_PHONE 发码、倒计时与错误，无 signIn、缓存刷新或导航副作用；设置换绑手机号继续使用它。闪念间直接发码、旧 OAuth 回调、票据和后端短信 API 均保留线上契约。

## 验证与发布

入口、注册地址重定向和共用发码回归先红后绿；新增守卫须做变异红绿验证。Web 必须完成 `pnpm test`、`pnpm typecheck`、`pnpm lint`、带 BACKEND_URL 的 `pnpm build`，并用 ego-browser 验证桌面、375px 手机、中英文 locale、next、微信确认返回、密码错误反馈和旧绑定不发起新请求。

R3 基于 R2 分支创建独立 Draft PR。R2 合并后才调整 base；R1 实际发布、正式小程序确认页、真实微信手机号授权、同号完整业务数据和生产等价主域 Cookie 验收仍是切换前置。源码与本地 mock 外部微信验证不是上线批准。

回退 Web 版本即可恢复旧入口，无数据库回退或用户数据处理；回退也会恢复短信依赖。所有未来 head/base 变化均需重新生成质量证据和评审。
