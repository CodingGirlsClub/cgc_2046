# Plan 2026-08-20-001 · 修复 #246：wechat 运行时动态模块编译竞态

## 根因（scout 2026-08-20 取证，HEAD c6bb1e6）

**三层竞态叠加，全程零外呼（端点全 mock）**：

1. **确定性模块名 + check-then-act**：登录 phoneCode 分支 → `Client.fetch_phone_by_code`（`client.ex:478-489`）→ `WechatClient.fetch`（`wechat_client.ex:63-84`）→ SDK `WeChat.build_client`（`deps/wechat/lib/wechat.ex:186-204`）运行时 `Module.create` 编译 `WechatClient.Client#{phash2(appid,secret)}`——appid/secret 来自固定测试配置（`config.exs:54-55`）→ 模块名**全 VM 确定性唯一**。`persistent_term.get → nil` 后双进程同时进入 build（`wechat_client.ex:68-80` 无锁窗口）。
2. **全局编译器 flag 竞态**：SDK `build_client` 用 `Code.compiler_options(ignore_module_conflict: true)` 翻转**全局**标志（非进程局部、非异常安全，raise 时泄漏）。`wechat_pay_test.exs`（`async: true`）的 `WeChat.Pay.build_client`（`pay.ex:144-162`）并发翻转——其 reset false 落在对方 `Module.create` 冲突检查前 → 后建者读 flag=false 且模块已存在 → **`CompileError: module already defined`**（或旧代码执行中 → `{:error, :not_purged}`）→ raise。
3. **异常被吞成静默失败**：resolver `try/rescue _`（`graphql_schema.ex:632-633`）把任何异常归一化 `authentication_failed` → `signInWithPlatform == nil` → `payload["id"]` 得 nil（失败点 `graphql_sign_in_with_platform_test.exs:152`）。enrollment 侧同源：`content_check` → `WechatClient.fetch` raise 无捕获（`enrollment_test.exs:682` 族）。

**次链（P3，仅 pay 测试自身）**：`:current_fingerprint` 全局键（`wechat_pay.ex:210,274-283`）+ cleanup（`wechat_pay_test.exs:230-235`）跨 async 用例 terminate 仍在运行的 child。

**触发最小集合**：`graphql_sign_in_with_platform_test`（async:true）+ `enrollment_test`（async:true）+ `wechat_pay_test`（async:true，flag 翻转器）。

**既有约定缺口**：「串行防跨用例污染」（`client_test.exs:2-3` 注释，async:false）已被 client/miniprogram_code/notification_service/graphql_miniprogram_code/url_scheme/share_scheme 采用，但漏了这两个 flaky 文件 + wechat_pay_test。

## 实施单元（backend，单 PR）

### U1 test_helper 预构建（主修，消 P0/P1 的 miniprogram 侧触发面）

`test/test_helper.exs`：`ExUnit.start()` 后、测试运行前，串行调用一次 `Cgc2046.Miniprogram.WechatClient.fetch()`——确定性模块在异步测试开始前已建好并进 persistent_term，所有 async 测试恒 cache-hit，miniprogram 侧**永不二次 Module.create**。

- 对 `{:error, :wechat_not_configured}` 宽容忽略（config 缺失时不阻断测试启动）。
- 若 fetch 语义需要额外启动步骤（SDK GenServer/refresher），按模块现状处理并在报告记录——不修改 lib/ 语义。
- 注意 `:wechat_client_autostart false`（`test.exs:66-67`）与本预构建的关系：autostart 管应用启动时自动构建，预构建是测试基础设施显式触发，二者不冲突。

### U2 wechat_pay_test 串行化（辅修，消全局 flag 翻转器 + P3）

`wechat_pay_test.exs` `async: true → false`：

- 消掉并发 flag 翻转源（P1 的参与方）；
- 消掉 `:current_fingerprint` 全局键 + cleanup 跨用例 terminate 干扰（P3）；
- 对齐既有「串行防跨用例污染」约定；文件小，串行代价可忽略。

### U3 复现验证（先红后绿）

红链（修复前基线取证，writer 落地前跑）：

```bash
for i in $(seq 1 40); do
  MIX_ENV=test mix test \
    test/cgc_2046_web/graphql_sign_in_with_platform_test.exs \
    test/cgc_2046/events/enrollment_test.exs \
    test/cgc_2046/payments/wechat_pay_test.exs \
    --seed $RANDOM > /tmp/wechat_flake_$i.log 2>&1 \
    && echo "iter $i PASS" || { echo "iter $i FAIL"; break; }
done
```

（竞态是每 VM 首建的一次性事件，必须每轮新 BEAM；若 20 轮未复现改跑全量循环。）40 轮内出现 ≥1 败 = 红链成立。若基线 40+ 轮仍全绿，如实记录（竞态概率性），后绿验证标准相应放宽为「全量 ×2 seeds + 并发循环 40 轮零失败」。

绿链（修复后）：同一命令 40 轮全绿 + 全量 `--seed 1/2` 全绿。

## 验收标准

1. 红绿链闭合（或基线不可复现时按 U3 降级标准）。
2. `mix format --check-formatted` + `mix compile --warnings-as-errors`。
3. 全量 `MIX_ENV=test mix test --seed 1` 与 `--seed 2` **字面全绿**（1326/1326 ×2——本线就是最后一项 flaky 的收口）。
4. 复现循环 40 轮零失败。
5. 既有 async:false 约定文件零改动；`wechat_pay_test` 用例本体零改动（只动 `async` 属性与必要注释）。

## 非目标

- **不动 lib/ 生产代码**（`wechat_client.ex` / `wechat_pay.ex` / SDK deps 均不改）。宿主级 build_client 串行化（`:global.trans` 锁）作为可选治本方向记 PR body，当前触发面已被 U1+U2 归零，不投机。
- 不改 resolver 的 `rescue _` 归一化（防枚举语义，正确行为）。
- 不动其余 async:true 测试文件。
- 不为 wechat_pay_test 的 cleanup 逻辑重构（串行化已消其干扰面）。
