# 闪念间 / 金句墙 / 许愿树：角色与用户旅程盘点（现状）

> **目的**：动视觉之前，先把现在真正做成了什么盘清楚。本文只描述现状（每条带代码出处）和已核实的问题，**不提出新交互**。
> **范围**：微信小程序为主（`miniprogram/src`），辅以后端可见性规则（`backend/lib/cgc_2046/flashback`）与 web 端差异。
> **基线**：`origin/develop` @ `617704f8`（2026-09-25）。
> **状态**：草稿，待产品确认。

---

## 0. 先说结论

1. 用户不是一条轴能切完的：**身份**（决定能看到什么）和**场景**（正在做什么）是两件事，要分开盘。
2. 现有产品的功能面比上一版原型大得多：场次名册、看别人的卡、逐句雾化、三档金句授权 + 多句圈选、卡片四态、公开链接开关、附议表单、公开留言流、回响、期待……上一版原型几乎都没覆盖。
3. **新人（没有档案的人）今天能做的事**：读金句墙（一次一句、随便听一听、点赞、分享）、读许愿树 + 「我也期待」、写愿望。**看不到**时间长廊、场次统计、谁回来了。
4. 核实到 **5 个阻塞级问题**：①场次页登录死循环（已修）②小程序内无找回 ③分享卡「找回」落死页 ④小程序内寄出后**不可撤回**、也不能删除档案 ⑤登录与订阅授权共用限流额度。

## 1. 角色

### 1.1 身份（互斥，决定能看到什么）

| # | 身份 | 怎么判定 | 出处 |
|---|---|---|---|
| I1 | **已绑定 · 记忆线**（当年参加了） | 账号绑定了档案，`participation = attended` | `alumni_projection.ex` `resolve_person` |
| I2 | **已绑定 · 圆梦线**（当年报了名、没被录取） | 同上，`participation = not_selected` | 同上 |
| I3 | **持链接 · 未注册** | 本机存着有效 token，没登录；包括首程里点了「跳过，直接上墙」的人 | `flashback-journey`、`STORAGE_KEYS.flashbackToken` |
| I4 | **已登录 · 没档案 · 真新人** | 自动认领未命中（按登录手机号/邮箱匹配） | `tokens.ex` `claim_for_user`，`useRecovery` 的 `unmatched` |
| I5 | **已登录 · 没档案 · 换了号的老校友** | 后端看起来和 I4 **完全一样**，只有本人能区分 | 同上 |
| I6 | **未登录 · 无链接**（路人） | `flashback_auth_required` | `useRecovery` 的 `guest` |
| I7 | **已删除档案** | `deleted_at` 置位，从所有名册与投影中消失 | `roster_by_archive` |

平台维度：**微信全量端**有全部页面；**抖音 / 小红书裁剪端只注册了一个回访页** `pages/flashback`（渲染 `MyCard`），没有首程、长廊、场次、金句墙、许愿树（`app.config.ts` `cutPages`）。

### 1.2 场景（任何身份都可能进入）

| # | 场景 | 主要页面 |
|---|---|---|
| S1 | 首程：从专属链接进来，认出自己 | `flashback-journey` |
| S2 | 回访：闪念间 Tab | `flashback-corridor` |
| S3 | 看某一场、看别人的卡 | `flashback-event` |
| S4 | 经营自己的卡：写今天、雾化、寄出、金句授权、做成卡片、分享 | `MyCard`、`flashback-today` |
| S5 | 听金句 | `flashback-voices` |
| S6 | 许愿树：读、期待、出力、许愿、留言、看回响 | `flashback-wishes`、`flashback-wish-write`、`flashback-my-wishes`、长廊愿望段 |
| S7 | 被分享进来：卡片 / 单句金句 / 单个愿望 / 整墙 / 整树 | `flashback-shared-card`、`?quoteId=`、`?wishId=` |
| S8 | 通知回流：回响提醒 | 订阅场景 `flashback_wish_echo`（小程序唯一的闪念间订阅） |

## 2. 可见性：谁能看到谁的什么

后端硬规则（`alumni_projection.ex` 模块头「可见性铁律 R12」+ `attach_content`）：

- 名册 = 当年**参加的**和**报了名没录取的**混排，按报名先后，不按身份分区；
- **结构化卡**（姓氏隐名「王\*\*」+ 城市 + 年份 + 当年职业）对全部名册成员默认可见；
- **内容层**（当年答案雾化版 + 今天摘要）只对**已寄出上墙**的人开放；撤回后立即退回结构化卡；
- 已寄出者显示**全名**（「她回来了即亮名」），未寄出者只有「王\*\*」；
- 他人答案里雾住的句子，后端替换成占位、雾段 `text` 恒为空——**原文字符不进前端**；
- 社交媒体题不进墙；手机、邮箱不进任何查询列表。

| 能看到的内容 | I1/I2 已绑定 | I3 持链接 | I4/I5 没档案 | I6 路人 | 分享卡接收者 |
|---|---|---|---|---|---|
| 自己当年答案原文 | ✓ | ✓（凭链接） | — | — | — |
| **全部场次**的时间轴与名册结构化层 | ✓（不止自己那一场） | ✓ | ✗ | ✗ | ✗ |
| 他人内容层（仅已寄出者，雾化后） | ✓ | ✓ | ✗ | ✗ | ✗ |
| 场次统计（报名 / 走进教室 / 已回来） | ✓ | ✓ | 仅从深链进场次页时 | 仅从深链进场次页时 | ✗ |
| 金句墙 | 读 + 赞 + 授权自己的句子 | 读 + 赞 + 授权 | 读 + 赞 | 读 + 赞 | 读 |
| 许愿树 | 读 + 期待 + 出力 + 许愿 | 读 + 期待（出力、许愿要登录） | 同 I1 | 读 + 期待（其余要登录） | 读 |
| 某人分享出来的卡 | ✓ | ✓ | ✓ | ✓ | ✓（只读、公开预览版） |

> 注意：设计文档 R32 规定路人可见「时间长廊统计层」。**web 公开首页做了**（`public-home.tsx`），**小程序访客首页没做**——统计只在场次页路人态出现。

## 4. 分身份旅程（按现状走一遍）

⚠ = 断点或体验问题；编号对应 §5。

**I1 记忆线校友 · 第一次（收到专属链接）**
1. 点链接 → 首程：快门 →「还记得是哪一场吗」→ 显影，看到当年的自己 → 翻面写今天 → 寄出（**此刻已上墙**）
2. 浮层二选一：「微信一键收好」（登录 + 认领并作废链接）/「跳过，直接上墙」
3. 进长廊，弹一次金句授权引导 →「选一句试试」→ 三档 + 圈选
4. 逛：点城市堆 → 场次页 → 点已回来的人看她的卡 → 回环去下一场 / 看看未来
5. 做成卡片 → 保存图片 / 开公开链接分享
6. ⚠ 如果她想撤下寄出的卡：小程序里做不到（→ P1-4）

**I1 记忆线校友 · 回访（已绑定）**
1. 闪念间 Tab → 长廊（新身份首次会有快门仪式）→ 今天格居中定位
2. 写今天 / 改雾化 / 调授权 / 看场次 / 许愿

**I2 圆梦线（当年没被录取）**
- 小程序里与 I1 **完全同一条路**。⚠ 问答题是「还记得……是哪一场吗」，可她当年没去；设计文档里的**信封开场**、名册上的「当年报了名」徽标，web 做了，小程序没有（→ P2-11）

**I3 持链接 · 未注册**
- 首程寄出后点「跳过」→ 长廊凭本机 token 正常使用，可写今天、雾化、授权、留言
- ⚠ 许愿、出力要登录；⚠ 换手机或清缓存即失联，而她的卡已经公开在墙上（→ P2-15）

**I5 换了号的老校友**
1. 闪念间 Tab → 访客首页 →「找回你的那一张」→ 登录 → 自动认领未命中
2. 看到「暂时还没找到你的那一张……没有历史档案，也可以从今天开始」+「写下我的愿望」
3. ⚠ 小程序里**没有**「换个手机号 / 邮箱再找」，只能去网页端（→ P1-2）
4. ⚠ 若从深链进了场次页，修复前会被反复要求登录（→ P1-1，已修）

**I4 真新人**
1. 闪念间 Tab → 访客首页：一句金句 + 金句墙 / 许愿树入口 + 「找回你的那一张」
2. 不登录也能：读金句（一次一句、随便听一听）、点赞、分享；读许愿树、「我也期待」；写愿望（提交时登录）
3. ⚠ 首页的主按钮「找回你的那一张」跟她无关；如果她点了，登录后会看到「暂时还没找到你的那一张」——**一句安慰失败者的话，可她并没有失败**（→ P2-6）
4. ⚠ 看不到时间长廊、场次统计、谁回来了（→ P2-12）

**I6 路人**
- 同 I4 登录前；从深链进场次页时只看到统计 + 登录引导

**分享卡接收者**
1. 点「闪念间 · 一张卡」→ 只读的公开卡
2. 「找回我的闪念间」→ ⚠ 落到不带链接的首程页：「没有找到这张邀请函。检查一下链接……」（→ P1-3）
3. 「去金句墙」→ 正常

**单句金句 / 单个愿望的分享接收者**
- 落到对应阅读器并定位到那一句 / 那一条；已收回有专门的空态

### P3 需要产品决定

- I4 / I5 后端同形，必须由用户自己选（不给选择就会误伤老校友）
- 新人的主路径是什么：听金句？许愿？报名下一场？可以不止一个，但首页的主次要定
- 长廊撤掉的 1024 横幅要不要回来（注释：活动推广归发现页）

## 7. 本轮视觉重构的边界

**改（只动视觉层）**
- 色彩 token：纸 / 墨 / 青 / 火 / 金 / 暗，替换现在灰底 + 品牌橙 + 山河青绿三套硬编码

- Tab 栏外观一套，不随页面变色、不换图标；Unicode 字符换成线性图标
- 「找回你的那一张」的视觉权重（位置不变，只改它在层级里的分量）
- 已有的暗场（首程快门、长廊快门仪式、开卡层遮罩）按「暗房」统一质感

**不改**
- 所有页面的信息架构、导航、交互、文案、流程
