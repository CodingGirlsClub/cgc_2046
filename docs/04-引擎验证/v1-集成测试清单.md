## F2 🟡 hibernate/thaw 未覆盖 deadline 到点唤醒 → cancel 路径（集成测试）

- **状态**：⬜ 待办（v1 集成测试）
- **背景**：POC-2 G1 A1–A5 全 PASS 覆盖了「waiting 挂起 → 信号到达 thaw → 恢复执行」，但
  **「挂起期间 deadline 到点自动唤醒并 cancel」未验证**。报名截止 / 审批超时均依赖该路径。
- **登记动作**：补集成测试——
  1. 恢复时检查 deadline → Emit cancel（或 Schedule Directive）；
  2. 断言 waiting 超时后 run 转 cancelled；
  3. 断言截止后 `submitted` 信号不再放行（SignalMatch 拒绝并回执「报名已截止」）。
- **验收标准**：
  - waiting 挂起期间 deadline 到点 → run 终态 cancelled（含已有 pending Enrollment 置 cancelled）；
  - 截止后到达的 `enrollment.submitted` 被拒绝放行，不产生副作用；
  - 测试覆盖 Schedule Directive 与「恢复时检查 deadline → Emit cancel」两条实现路径之一（v1 至少实现一条）。
- **关联文档**：

## F8 🟡 auto_approve 模式 10s 倒计时自动决策风险（实现约束）

- **状态**：⬜ 待办（v1 实现约束）
- **背景**：高风险工具（assign_role / create_invitation / 审批类）确认流的 auto_approve 模式
  为 10s 倒计时自动决策——倒计时内无人工介入即自动通过，存在误放行风险。
- **登记动作（v1 约束）**：
  - **v1 默认关** auto_approve，或**仅限白名单工具**启用；
  - 白名单外的确认流必须人工确认，禁止默认自动通过。
- **二期预留**：加冷却期——同工具短时间重复调用不再 auto_approve。
- **验收标准**：
  - v1 配置中 auto_approve 默认关闭；白名单工具清单显式维护；
  - 白名单外工具触发确认流时无倒计时自动通过路径。
- **关联文档**：
  - `docs/diagrams/REVIEW-FINDINGS.md` F8
  - `docs/00-CGC平台设计总纲.md` D8 确认流
