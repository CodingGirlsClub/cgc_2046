## 4. 注意点（非阻断）

1. **bcrypt_elixir** 声明 `BSD-3-Clause / ISC / BSD-4-Clause` 三选一（hex 多选语义：使用者任选其一）。采用 **BSD-3-Clause 或 ISC** 条款即可与 AGPL-3.0 兼容；BSD-4-Clause（带广告条款）与 GPL 系冲突，不选择它。
2. **caniuse-lite**（CC-BY-4.0）要求保留数据署名——npm 包自带 LICENSE 文件，无额外动作。

## 5. 负面结论（重点）

- **无 GPL-2.0-only**：GPL-2.0 是唯一与 AGPL-3.0 不兼容的常见许可，全链路 **零命中**。
- **无 UNKNOWN / proprietary / SSPL / BUSL / Elastic License**：所有包均有明确许可声明。

## 6. 新增依赖时的合规检查点

新增依赖前（呼应 `CONTRIBUTING.md` §6 依赖纪律），按序检查：

1. License 是否为宽松许可（MIT/Apache-2.0/BSD/ISC/0BSD/CC0）或 AGPL-3.0 兼容的弱 copyleft（MPL-2.0、LGPL-3.0+、EPL-2.0）；
2. **禁止**：GPL-2.0-only、SSPL、BUSL、Elastic License、proprietary、无许可声明；
3. 原生二进制/系统库（如 libvips 类）走动态链接/进程边界使用，不修改其源码；
4. 数据类包（caniuse 类）保留其自带署名与 LICENSE 文件；
5. 无法判断时，先开 issue 讨论再引入。

## 7. 结论

本项目全链路依赖（后端 67 + 前端 1467 + 运行时 2）与 **AGPL-3.0** 兼容，无阻断项、无 GPL-2.0 污染、无专有许可。可安全地以 AGPL-3.0 对外发布。
