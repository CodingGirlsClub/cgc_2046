# 依赖引入规则（License 合规，持续约束）

> **性质**：本项目新增依赖时必须遵守的**持续规则**（人、Agent、CI 三方共同执行）。
> **与审计文档的关系**：[依赖许可证审计.md](./依赖许可证审计.md) 是 2026-08-05 的**快照证据**（当时全量依赖的兼容性结论）；本文件是**面向未来的约束**。两者分离：审计会过时，规则不。
> **底层许可**：项目采用 [AGPL-3.0](../../LICENSE)（GNU Affero General Public License v3.0）。

---

## 1. 一句话规则

> 新增任何依赖（Hex / npm / 原生库 / 二进制），其许可证必须与 AGPL-3.0 兼容；**违反即不可引入**，无论其功能多有用。

## 2. 允许引入（白名单）

| 类别 | License | 说明 |
| ------ | --------- | ------ |
| 宽松许可 | MIT、Apache-2.0、BSD-2-Clause、BSD-3-Clause、ISC、0BSD、CC0-1.0、Unlicense、BlueOak-1.0.0、MIT-0、Python-2.0、Zlib | 直接兼容，无需额外动作。Zlib 于 2026-08-09 由 human 裁定加入（OSI 批准 permissive，AGPL-3.0 兼容；`MIT AND Zlib` 声明经此放行） |
| 弱 copyleft（AGPL 兼容） | MPL-2.0、LGPL-3.0+（LGPL-3.0-only / LGPL-3.0-or-later）、EPL-2.0 | 允许以库形式链接/组合使用，**不得修改其源码后闭源分发** |
| 数据/内容类 | CC-BY-4.0 等 CC-BY 系 | 仅用于数据（如 caniuse-lite、spdx-exceptions），必须保留其自带署名与 LICENSE 文件。spdx-exceptions（CC-BY-3.0）于 2026-08-09 按本类裁定放行（SPDX 标准数据包，无代码） |
| 多选声明 | 如 `BSD-3-Clause / ISC / BSD-4-Clause` | 使用者**任选其一**；必须选择其中与 AGPL 兼容的一项（如 BSD-3-Clause），不得选含广告条款项（BSD-4-Clause） |

## 3. 禁止引入（黑名单，CI 硬性拦截）

| License | 原因 |
| --------- | ------ |
| **GPL-2.0-only / GPL-2.0-or-later** | 与 AGPL-3.0 不兼容（FSF 明确），无法组合 |
| **SSPL（MongoDB）**、**BUSL**、**Elastic License 2.0** | 非 OSI 开源许可，与 AGPL 精神冲突 |
| **proprietary / commercial-only** | 专有许可 |
| **无许可声明（UNKNOWN）** | 无法确认权利归属，法律风险 |
| 混合声明中**含**上述项的 | 若声明为"多选"且可避开则允许（见上）；若为"必须全部遵守"则禁止 |

## 4. 特殊形态的检查要点

| 形态 | 检查要点 |
| ------ | --------- |
| 原生库 / 系统二进制（如 libvips） | 走动态链接或进程边界使用；不修改其源码、不静态链接进发布物；license 为 LGPL 系可接受 |
| 传递依赖 | 只查直接依赖不够——新依赖拉入的**传递依赖**同样受本规则约束（CI 扫描覆盖全树） |
| 工具链 / 构建期依赖 | 同样受约束（如 lightningcss、axe-core 均为 MPL-2.0，允许） |
| 数据包（browserslist/caniuse 类） | 保留署名，不删 LICENSE 文件 |

## 5. 执行机制（三层）

| 层 | 载体 | 作用 |
| ---- | ------ | ------ |
| 人 | `CONTRIBUTING.md` §6 + PR 模板勾选项 | 引入者在提交前自检 |
| Agent | `AGENTS.md`（根 + backend/ + web/）红线条款 | Agent 引入依赖时自动遵守 |
| 机器 | CI：`mix cgc2046.check_licenses` + `pnpm check:licenses` | **最终兜底**：黑名单命中即 CI 红灯 |

## 6. 不确定时怎么办

- 无法确认许可证、或遇到本表未列出的 License（如 AGPL-3.0 本身的依赖、GPL-3.0-only、EPL-1.0、WTFPL、CC-BY-SA）→ **先开 issue 讨论，不直接引入**；
- 判断标准：FSF 兼容性矩阵（`https://www.gnu.org/licenses/license-list.html`）+ OSI 列表交叉验证；
- 结论以 issue 拍板为准，并回填本文件更新规则。
