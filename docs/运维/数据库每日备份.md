# 数据库每日备份

生产库 `cgc_2046_prod` 的自动备份机制（上线 checklist #213）。脚本源文件在本目录（`scripts/backup/`），以下为服务器侧安装形态与恢复手册。

## 机制

每日 03:30（Asia/Shanghai）root 经 `/etc/cron.d/cgc-backup` 触发：

```
pg_dump（PG 容器内，custom 格式）
  → age 公钥加密（明文即刻删除，绝不出服务器）
  → COS 上传（内网 endpoint，同地域免流量费）
  → 本地保留近 7 天（COS 永久，桶侧生命周期另配）
```

| 服务器路径 | 内容 | 源文件 |
|---|---|---|
| `/usr/local/bin/cgc-backup` | 备份主脚本 | `scripts/backup/cgc-backup.sh` |
| `/usr/local/bin/cos-put.py` | COS 上传（纯标准库） | `scripts/backup/cos-put.py` |
| `/etc/cron.d/cgc-backup` | 定时片段 | `scripts/backup/cgc-backup.cron` |
| `/opt/cgc/backup/age.key` | age 私钥（解密用，**另存密码管理器一份**） | — |
| `/opt/cgc/backup/cos.env` | COS 凭证（`COS_SECRET_ID/KEY/BUCKET/REGION`） | — |
| `/var/log/cgc-backup.log` | 运行日志 | — |

COS 对象键：`db-backup/cgc_2046_prod-<date>.dump.age`。

## 依赖

- `age`：**必须 apt 安装**（`sudo apt-get install -y age`）。勿用临时二进制——2026-08-21~31 事故：宿主机 age 丢失后脚本每天在加密一步中断（`set -eu`），COS 上传连续 10 天未执行，唯一的异常信号是日志里一行 `age: not found`。
- python3、docker（PG 容器名 `cgc2046-backend-postgres`）。

## 巡检

```bash
# 昨日应有一行 "backup done"，且无 WARN
ssh cgc_production_server 'sudo tail -5 /var/log/cgc-backup.log'
# 本地应只余近 7 天 .age 密文（无明文 .dump）
ssh cgc_production_server 'sudo ls /opt/cgc/backup/dumps/'
```

## 灾难恢复

```bash
# 1. 取密文（本地 7 天内直取；更早从 COS 控制台下载 db-backup/ 前缀对象）
sudo ls /opt/cgc/backup/dumps/
# 2. 解密（age.key 即私钥）
sudo age -d -i /opt/cgc/backup/age.key \
  -o /tmp/restore.dump /opt/cgc/backup/dumps/cgc_2046_prod-<date>.dump.age
# 3. 灌入（临时库核对内容，确认后再定回灌范围）
sudo docker cp /tmp/restore.dump cgc2046-backend-postgres:/tmp/
docker exec cgc2046-backend-postgres createdb -U cgc_2046 -T template0 cgc_2046_restore
docker exec cgc2046-backend-postgres pg_restore -U cgc_2046 -d cgc_2046_restore --no-owner /tmp/restore.dump
# 4. 清理
sudo rm /tmp/restore.dump
```

选择性回灌（只搬部分表，例如只要用户与订单）用 `pg_restore --data-only --table=<t>`，注意外键顺序与现库主键冲突（先在临时库核对，再以 SQL 迁移）。
