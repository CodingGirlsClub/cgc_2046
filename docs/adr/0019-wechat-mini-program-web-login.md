# ADR-0019：Web 通过微信小程序确认登录，沿用手机号账号规则

网站微信 OAuth 的新用户最终仍需短信绑定，短信故障会阻断注册。用户选择由小程序取得平台验证后的手机号并确认 Web 登录，继续复用现有 User 与 UserIdentity，不引入无手机号建号、跨账号合并或业务数据迁移。小红书使用同一手机号时沿用同一 User；不同号码和既有重复账号不自动归并。

Web 发起短期请求，小程序只负责认证与显式批准，原浏览器持有独立 HttpOnly 证明并领取 Web 会话。公开小程序码不能用来领取；确认前不会签发 Web token；消费事务同时处理票据和 Web token，保留小程序会话。响应丢失时仅允许匹配本次 JTI 的原浏览器恢复，不能无限重放票据。沿用 [ADR-0008](0008-browser-session-single-origin.md) 的单一浏览器主域，不扩大 Cookie Domain。

选择有界轮询而不是新增 WebSocket 服务。小程序码与 URL Link 复用既有 SDK 的 token 生命周期；新启动请求直接使用 Req，以落实单次 8 秒超时、零自动重试和不记录带 token 的请求 URL，避免改变旧 SDK 调用方的重试行为。刷新旋转浏览器证明，但沿请求链保留稳定限流键，防止刷新重置额度。

后端和小程序能力必须先上线，小程序正式确认页与真实手机链路通过验收后才能切换 Web 入口。旧网站 OAuth API/回调仍是已上线契约，不在本次删除，也不作为新流程失败后的自动短信 fallback。退回 Web 版本不会迁移用户数据，但会恢复旧入口的短信依赖。

实现与验收范围见[方案](../plans/2026-09-30-1206-feat-wechat-mini-web-login-plan.md)。
